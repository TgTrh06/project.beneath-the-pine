# Pre-launch core migration baseline

`0000_core_baseline.sql` and `meta/` are generated by Drizzle Kit from the reviewed module schemas. The baseline includes identity/profile, Circle, Pact, focus/session, Open Seed, milestone and allowlisted event storage.

Review the target before explicitly running `pnpm --filter @beneath-the-pine/api db:migrate`. There is no admin seed or role bootstrap.

This replaces the identity-only pre-launch baseline. Recreate only an explicitly disposable development database that used the old migration; never apply the replacement as a forward production migration. The implementation did not execute this migration against an existing database.

`0001_white_spacker_dave.sql` is a forward migration adding per-account Circle invitation declines. It has cascading foreign keys to invitation and account, and contains no destructive data change. Review the generated SQL and migration history before applying it. A code rollback can leave the unused table in place; dropping it later would delete recorded decline choices and needs a separate review.

`0002_camp-rename.sql` is the forward-only Circle → Camp contract migration. It renames four enum types, five tables, five foreign-key columns, their constraints and indexes, and three stored product event names. Rows, UUIDs and relationships are retained. Old Circle API clients and `#circle` links are incompatible after this migration; deploy code and migration as one reviewed release. First verify a copy of the old schema with existing rows and a fresh database. Do not run this against the user's local database or a pilot/production database as part of repository validation. A rollback to old code requires a separately reviewed reverse migration or a restored backup; code-only rollback is unsafe.
